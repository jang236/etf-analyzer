## 읽기 규칙

- 레퍼런스DB는 1,700행이 넘는다. 전체를 읽지 말고 필요한 열만 범위로 읽는다. 예: `'📚레퍼런스DB'!C2:Q3004` 를 한 번 읽어 로컬에서 거른다.
- 주제 후보 필터: 쇼츠 = N, 길이 ≥ 3, 주제☑ = FALSE, 키워드에 브리프 키워드 포함, 배수 내림차순.
- 핫비디오(주제 무관 구조 참고): 쇼츠 = N, 배수 상위 30. 인트로 구조 참고는 📝레퍼런스대본 유형 인트로 중 출처가 있는 것.
- 제작보드의 기존 "주제후보" 행은 부코드가 이미 골라둔 후보다. 주제 후보 표에 항상 함께 보여준다.
- 배수, 조회수, 구독자는 시트 값만 쓴다. 지어내지 않는다.

## 쓰기 규칙

- 기존 행을 덮어쓰지 않는다. 제작보드는 프로젝트의 행 하나만 갱신한다 (번호 열로 행을 찾는다).
- 제작보드 "상태" 값: 주제후보 → 기획 승인 대기 → 소재 수집 → 시연 승인 대기 → 대본 작성 → 최종 승인 대기 → 완성.
- 제작보드 "썸네일 문구" 형식은 기존 관례를 따른다: `[후보1·추천 점수] 문장 (ref: 채널 x배수)` 한 줄씩, 확정되면 `[확정 날짜]`.
- 레퍼런스대본에 자막을 추가할 때 번호는 마지막 번호 + 1, 유형은 "본문", 출처URL 필수.

## 뷰트랩 자동 수집기

🔑상태 탭이 수집기의 토큰 상태다. 2026-08-17에 만료됐고, PC의 수집기 `.env`에 `VIEWTRAP_TOKEN`을 갱신해야 새 수집분이 들어온다. 그 전까지는 부코드가 뷰트랩에서 직접 시트에 붙여 넣는다.
