## 🧭작업실 탭 (사용자 화면, sheetId 4242)

부코드가 보는 유일한 화면이다. 시스템은 결정이 필요할 때 여기에 쓰고, 부코드의 선택을 여기서 읽는다. 채팅으로 답해도 되고 셀에 적어도 된다.

| 구역 | 범위 | 누가 쓰나 | 내용 |
| --- | --- | --- | --- |
| ① 지금 할 일 | A6:G11 | 시스템 | 프로젝트, 상태, 다음 할 일, 자세히, 어디서(채팅/시트), 링크, 갱신일. 프로젝트당 한 줄, 같은 프로젝트면 덮어쓴다 |
| ② 결정 입력 | A16:H35 | 후보는 시스템, "내 선택"과 "이유"는 부코드 | 프로젝트, 결정 지점, 번호, 후보, 추천(★), 내 선택, 이유, 처리. 15행은 예시라 건드리지 않는다 |
| ③ 진행 중인 영상 | A39 수식 | 자동 (QUERY) | 제작보드에서 주제후보 아닌 행 |
| ④ 사용법 | A53:B61 | 고정 | 수정하지 않는다 |
| ⑤ 최근 하이라이트 | A65:F69 | 시스템 | 하이라이트 탭의 최근 5줄 복사 |

결정 입력 프로토콜:
- 결정 지점에 도달하면 ② 의 빈 줄부터 후보를 한 줄씩 쓴다 (프로젝트, 결정 지점 예: "기획 승인 · 주제", 번호, 후보 한 줄, 추천이면 ★, 내 선택 빈칸, 이유 빈칸, 처리 빈칸). ① 의 그 프로젝트 줄을 "결정 대기"로 바꾸고 "어디서"를 "시트 ② 또는 채팅"으로 적는다.
- 다음에 "진행해"가 오면 먼저 ② 를 읽는다. "내 선택" 열에 ✔, 번호, "추천대로"가 있으면 그것을 결정으로 쓰고, "이유" 열이 있으면 하이라이트 "왜 좋았나" 앞에 그대로 적는다. 채팅 답과 셀이 둘 다 있으면 채팅이 우선한다.
- 처리한 줄은 "처리" 열에 날짜를 적는다. 처리된 줄은 다시 읽지 않는다. 20줄이 넘으면 처리된 줄부터 지워 자리를 만든다.
- 결정이 끝나면 ① 의 상태를 다음 구간으로 바꾼다.

## 읽기 규칙

- 레퍼런스DB는 1,700행이 넘는다. 전체를 읽지 말고 필요한 열만 범위로 읽는다. 예: `'📚레퍼런스DB'!C2:Q3004` 를 한 번 읽어 로컬에서 거른다.
- 주제 후보 필터: 쇼츠 = N, 길이 ≥ 3, 주제☑ = FALSE, 키워드에 브리프 키워드 포함, 배수 내림차순.
- 핫비디오(주제 무관 구조 참고): 쇼츠 = N, 배수 상위 30. 인트로 구조 참고는 📝레퍼런스대본 유형 인트로 중 출처가 있는 것.
- 제작보드의 기존 "주제후보" 행은 부코드가 이미 골라둔 후보다. 주제 후보 표에 항상 함께 보여준다.
- 배수, 조회수, 구독자는 시트 값만 쓴다. 지어내지 않는다.

## 쓰기 규칙

- 기존 행을 덮어쓰지 않는다. 제작보드는 프로젝트의 행 하나만 갱신한다 (번호 열로 행을 찾는다).
- 제작보드 "상태" 값: 주제후보 → 기획 승인 대기 → 소재 수집 → 시연 승인 대기 → 대본 작성 → 최종 승인 대기 → 완성.
- 제작보드 "썸네일 문구" 형식은 기존 관례를 따른다: `[후보1·추천 점수] 문장 (ref: 채널 x배수)` 한 줄씩, 확정되면 `[확정 날짜]`.
- 레퍼런스대본에 자막을 추가할 때 번호는 마지막 번호 + 1, 유형은 "본문", 출처URL 필수.
